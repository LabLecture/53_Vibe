# 컴포넌트 설계서 — cs.AI 신규 논문 주간 알림

| 컴포넌트 | 책임 | 하지 않는 것 | 의존하는 것 |
|---|---|---|---|
| Scheduler | 정시 트리거, 실행 실패·누락 감지, 재시도 수행, 재시도 한도 초과 시 실행 중단·에러 로깅 (UC-1, UC-3) | 논문 수집·필터링 로직 직접 수행, Discord 메시지 포맷 구성 | Crawler, Notifier |
| Crawler | arXiv cs.AI 카테고리 조회, 최근 7일 신규 논문 필터링, 조회 실패 에러 로깅 (UC-1) | 중복 여부 판단, 전송 이력 저장, Discord 전송 | arXiv API |
| Store | 전송 이력 저장·조회, 신규 수집 목록과 이력 대조해 미전송 논문만 선별 (UC-2) | 논문 수집, Discord 전송, 재시도 판단 | 로컬 DB(SQLite) |
| Notifier | 전송 대상 논문을 Discord 채널로 발송, 0건/전송 생략 케이스 처리, 전송 실패 에러 로깅 (UC-1, UC-2, UC-4) | 전송 대상 선별(중복 제거), 재시도 스케줄링 | Discord API, Store(전송 대상 확정 결과) |

## 비고
- 4개 컴포넌트는 실습 저장소 스캐폴딩(`crawler/`·`store/`·`notifier/`) + 오케스트레이션(Scheduler) 구조와 1:1 대응.
- UC-3 "재시도 실패 시 알림 발송 대상"과 UC-1/2 "신규 논문 0건 정책"은 유스케이스 문서의 미확정 항목 그대로 — 컴포넌트 책임 분리와 별개로 정책 확정 필요.
