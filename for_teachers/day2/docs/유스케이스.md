# 유스케이스 — cs.AI 신규 논문 주간 알림

## UC-1: 주간 신규 논문 자동 수집·알림 발송
- 액터: 스케줄러(시스템)
- 목적: 매주 월요일 정해진 시각에 cs.AI 신규 논문을 자동 수집해 Discord로 전송한다.
- 사전조건: 스케줄 등록됨, arXiv API·Discord API 접근 가능
- 기본 흐름: 스케줄 트리거 → arXiv cs.AI 카테고리 조회 → 최근 7일 이내 신규 논문 필터링 → Discord 채널로 전송
- 예외 흐름:
  - arXiv 조회 실패 → 에러 로깅
  - Discord 전송 실패 → 에러 로깅

## UC-2: 중복 논문 재전송 방지
- 액터: 시스템(알림 파이프라인)
- 목적: 이미 전송한 논문이 다시 전송되지 않게 걸러낸다.
- 사전조건: 이전 전송 이력 저장돼 있음
- 기본 흐름: 신규 수집 논문 목록 확보 → 전송 이력과 대조 → 미전송 논문만 선별 → 전송 대상 확정
- 예외 흐름:
  - 전송 이력 조회 실패 → 에러 로깅
  - 신규 논문 전부 이미 전송된 이력 → 전송 생략

## UC-3: 스케줄 실행 실패 시 재시도
- 액터: 스케줄러(시스템)
- 목적: 정시 실행 실패·누락 시 재시도해 정시 발송률을 유지한다.
- 사전조건: 스케줄 실행 모니터링 설정됨
- 기본 흐름: 예정 시각 도달 → 실행 시도 → 실패·누락 감지 → 재시도 수행
- 예외 흐름:
  - 재시도도 실패 → 알림 발송
  - 재시도 한도 초과 → 에러 로깅 후 실행 중단

## UC-4: 연구자가 Discord에서 주간 알림 확인
- 액터: 연구자/개발자(사용자)
- 목적: 매주 월요일 걸러진 cs.AI 신규 논문 목록을 Discord에서 확인한다.
- 사전조건: Discord 채널에 알림 발송 완료
- 기본 흐름: Discord 알림 수신 → 채널에서 메시지 확인 → 논문 목록 열람
- 예외 흐름:
  - 발송 자체가 실패해 알림 미수신 → UC-1 예외 흐름 참고
  - 알림 시점에 미접속 → 이후 채널 히스토리에서 확인
