# 인터페이스 정의서 — cs.AI 신규 논문 주간 알림

`컴포넌트설계서.md`의 책임 분리를 파이썬 함수 시그니처로 구체화한다. 각 함수는 타입 힌트 필수, 실패 시 동작을 명시한다.

## 공통 타입

```python
from dataclasses import dataclass
from datetime import datetime

@dataclass
class Paper:
    arxiv_id: str
    title: str
    authors: list[str]
    url: str
    published_at: datetime
```

## Crawler

```python
def fetch_recent_papers(category: str = "cs.AI", days: int = 7) -> list[Paper]:
    """arXiv 지정 카테고리에서 최근 N일 이내 신규 논문을 조회한다."""
```
- 실패 시 동작: arXiv API 조회 실패 시 에러 로깅 후 `CrawlerFetchError` 예외를 던진다(값으로 실패를 표현하지 않음).
- 반환값: 최근 N일 이내 신규 논문 목록. 신규 논문이 없으면 **빈 리스트**(예외 아님).

## Store

```python
def get_unsent_papers(papers: list[Paper]) -> list[Paper]:
    """신규 수집 논문 목록을 전송 이력과 대조해 미전송 논문만 선별한다."""
```
- 실패 시 동작: 전송 이력 조회 실패 시 에러 로깅 후 `StoreQueryError` 예외를 던진다.
- 반환값: 미전송(신규) 논문 목록. 입력 논문이 전부 이미 전송된 이력이면 **빈 리스트**(UC-2 "전송 생략"의 판단 근거 — 생략 여부 자체는 호출자가 빈 리스트로 판단).

```python
def save_sent_papers(papers: list[Paper]) -> int:
    """전송 완료된 논문을 전송 이력에 저장한다."""
```
- 실패 시 동작: 저장 실패 시 에러 로깅 후 `StoreWriteError` 예외를 던진다.
- 반환값: **신규로 저장된 건수**(int). 이미 저장된 항목은 중복 저장하지 않고 카운트에서 제외한다.

## Notifier

```python
def send_papers(papers: list[Paper]) -> bool:
    """전송 대상 논문 목록을 Discord 채널로 발송한다. 빈 리스트면 발송을 생략한다."""
```
- 실패 시 동작: Discord 전송 실패 시 에러 로깅 후 **예외를 던지지 않고 `False`를 반환**(Scheduler가 재시도 여부를 판단할 수 있도록 값으로 실패를 전달).
- 반환값: `bool` — 전송 성공 여부. `papers`가 빈 리스트면 전송을 생략하고 `True`를 반환한다(0건 안내 메시지를 보낼지는 **미확정 정책** — 컴포넌트설계서 비고 참고).

## Scheduler

```python
def run_weekly_job() -> bool:
    """정시 트리거로 Crawler → Store → Notifier 파이프라인을 실행한다."""
```
- 실패 시 동작: 파이프라인 내부 실패(Crawler/Store 예외, Notifier `False`)를 감지하면 `retry_job`을 호출해 재시도한다. 재시도 한도 초과 시 에러 로깅 후 실행을 중단하고 `False`를 반환한다(예외를 던지지 않음 — 호출측 스케줄 인프라가 성공/실패만 보면 되므로).
- 반환값: `bool` — 이번 회차 실행이 최종적으로 성공했는지 여부.

```python
def retry_job(attempt: int, max_attempts: int) -> bool:
    """실행 실패·누락 감지 시 재시도를 수행한다."""
```
- 실패 시 동작: 재시도 자체가 실패하면 `False`를 반환한다(예외 없음). 재시도 한도(`max_attempts`) 초과 처리는 호출자(`run_weekly_job`)의 책임 — 이 함수는 단일 재시도 1회의 성공 여부만 보고한다.
- 반환값: `bool` — 이번 재시도 성공 여부.
- **미확정**: "재시도도 실패" 시 알림 발송 대상(UC-3 예외 흐름)이 PRD에 특정되지 않아, 이 시그니처는 알림 발송 로직을 포함하지 않는다. 대상 확정 후 별도 함수(예: `notify_retry_exhausted(attempt: int) -> bool`)로 분리 예정.

## 대조표 — 유스케이스 예외 흐름 ↔ 인터페이스 계약

| 유스케이스 예외 흐름 | 대응 계약 | 비고 |
|---|---|---|
| UC-1: arXiv 조회 실패 → 에러 로깅 | `fetch_recent_papers`가 `CrawlerFetchError` 예외를 던짐(로깅은 예외 처리 내부) | 값이 아닌 예외로 표현 |
| UC-1: Discord 전송 실패 → 에러 로깅 | `send_papers`가 `False` 반환(로깅은 함수 내부) | 예외가 아닌 값으로 표현 — Scheduler 재시도 판단용 |
| UC-2: 전송 이력 조회 실패 → 에러 로깅 | `get_unsent_papers`가 `StoreQueryError` 예외를 던짐 | 값이 아닌 예외로 표현 |
| UC-2: 신규 논문 전부 이미 전송된 이력 → 전송 생략 | `get_unsent_papers`가 빈 리스트 반환 → `send_papers([])`가 `True` 반환(발송 생략) | 두 함수 조합으로 표현 |
| UC-3: 재시도도 실패 → 알림 발송 | **미표현** — `retry_job`은 발송 로직 없음 | 대상 미확정으로 계약 보류(컴포넌트설계서 비고와 동일 사유) |
| UC-3: 재시도 한도 초과 → 에러 로깅 후 실행 중단 | `run_weekly_job`이 에러 로깅 후 `False` 반환(예외 없음) | 한도 판단은 `run_weekly_job`이 수행, `retry_job`은 단일 시도만 담당 |
| UC-4: 발송 자체 실패 → 알림 미수신(UC-1 참고) | UC-1 행 재사용(`send_papers` → `False`) | 신규 계약 없음, UC-1과 동일 |
| UC-4: 알림 시점 미접속 → 이후 채널 히스토리 확인 | **인터페이스 계약 대상 아님** | Discord 클라이언트 동작이며 이 파이프라인 컴포넌트 책임 밖 |

미확정 2건(UC-3 알림 대상, 0건 시 "없음" 안내 여부)은 컴포넌트설계서 비고와 동일하게 **정책 확정 전까지 계약에 반영하지 않음**. 0건 정책은 위 `send_papers` 반환값 설명에 임시 동작(생략+`True`)으로 명시해뒀으니, 정책 확정 시 이 문서와 함께 갱신할 것.
